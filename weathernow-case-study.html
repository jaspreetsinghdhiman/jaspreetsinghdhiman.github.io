WeatherNow

A city weather dashboard that combines location search, current conditions and a five-day outlook in one responsive interface, using Open-Meteo data.

Project overview

WeatherNow is an independent frontend demo that retrieves location and forecast information from Open-Meteo. Visitors can search for a city or request their current browser location to load weather information.

Project status: Personal portfolio demonstration. Weather data depends on external API availability and an active internet connection.

Problem being addressed

Weather information can be difficult to scan when the current conditions, location and upcoming forecast are spread across separate screens. This project brings the key details into a single dashboard.

Design and UX decisions

The interface provides a city search field, location shortcut, current conditions summary and a five-day forecast. Search suggestions help users select a matching place instead of relying only on a free-text city name.

Main features

  • City search through the Open-Meteo geocoding API
  • Debounced city suggestions while typing
  • Current temperature and apparent temperature
  • Weather description, humidity and wind speed
  • Five-day high and low temperature forecast
  • Browser geolocation when the visitor grants permission
  • Loading, no-result and error feedback
  • Weather condition labels and icons mapped from weather codes

Implementation approach

The geocoding request resolves a city name into latitude and longitude. Those coordinates are then passed to the Open-Meteo forecast endpoint. The page reads current conditions and daily forecast arrays, maps weather codes to labels and icons, and builds the five forecast rows in the browser.

Frontend technologies

HTML5, CSS3, vanilla JavaScript, Fetch API, Geolocation API and Open-Meteo geocoding/forecast endpoints.

Responsive behaviour

The dashboard is designed to keep search and weather information readable across screen sizes. Shared site quality rules provide baseline responsive safeguards; the final experience should still be checked on actual mobile devices at narrow widths.

Challenges and technical decisions

City names can match multiple places, so the interface offers geocoding suggestions and displays the selected place name. Geolocation is optional and depends on browser permission. Weather-code mapping keeps the forecast descriptions consistent with the returned API values.

What visitors can test

Search for a city such as Chandigarh, London or Tokyo, choose a suggestion, inspect the current conditions and five-day outlook, or try the location button after granting permission.

Limitations

The dashboard requires an internet connection and depends on Open-Meteo endpoints. Location access is optional and permission-controlled. The current implementation is a forecast viewer rather than a severe-weather alert service, historical weather archive or long-term climate tool.

Future improvements

Potential improvements include unit switching, saved favourite cities, clearer API failure states, accessible keyboard navigation for city suggestions and a more explicit timestamp for the latest observation.
