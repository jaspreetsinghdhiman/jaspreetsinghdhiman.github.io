MarkStudio

A focused in-browser Markdown writing tool. Edit source text, preview the rendered document as you type, keep a draft in browser storage and download the Markdown file.

Project overview

MarkStudio is an independent portfolio demo that demonstrates a split writing-and-preview workflow. The editor is prefilled with a sample Markdown document, and the preview updates as the source text changes.

Project status: Personal frontend portfolio demonstration, not commissioned client work.

Problem being addressed

Writing Markdown is efficient, but users often need to switch between a text editor and a separate renderer to check headings, lists, code and tables. MarkStudio brings editing and preview into one browser interface.

Design and UX decisions

The page keeps the source editor and rendered preview close together so changes can be checked immediately. A starter document explains supported Markdown patterns, while the download action stays visible as a direct next step.

Main features

  • Live rendered preview while typing
  • Markdown headings, emphasis, lists, links, quotes, code blocks and tables through the Markdown parser
  • HTML sanitisation before preview insertion using DOMPurify
  • Draft persistence in browser localStorage
  • Download the current source as a .md file
  • Plain-text fallback preview if the Markdown or sanitisation libraries are unavailable

Implementation approach

The editor input event stores the current source in localStorage and calls the render function. When Marked and DOMPurify are available, the Markdown is parsed and the resulting HTML is sanitised before it is inserted into the preview. The download action creates a Markdown Blob and triggers a browser download.

Frontend technologies

HTML5, CSS3, vanilla JavaScript, Marked, DOMPurify, localStorage, Blob and browser download APIs.

Responsive behaviour

The editor and preview are presented as a writing workspace. The page uses the shared portfolio quality stylesheet for baseline responsive and focus-visible improvements. Exact device-specific visual behaviour should be checked on real mobile browsers before claiming pixel-perfect parity.

Challenges and technical decisions

Preview rendering uses DOMPurify after Markdown parsing rather than inserting parser output without sanitisation. Draft storage is intentionally browser-local, which keeps the demo simple but does not synchronise content between devices.

What visitors can test

Edit the sample Markdown, add headings or lists, check the live preview, refresh the page to verify browser-saved content, then download the source file.

Open MarkStudio demo ↗

Limitations

Drafts remain in the current browser storage and are not backed up to a server or shared across devices. The editor is not a collaborative writing service. Live Markdown rendering depends on the external parser and sanitiser libraries loading successfully.

Future improvements

Useful next steps could include a clear-draft control, copy-rendered-output action, export to HTML, adjustable editor/preview split and explicit storage status feedback.
